# Donate 实现规格

本文件固定产品规则及实现约束。界面参考见 [设计规范](design/README.md)，架构见[后端设计](backend-design.md)，实际配置与部署见[运行说明](operations.md)。正式前后端已建立，真实身份提供方、商户与生产环境由部署联调，本版本不导入旧数据。

## 架构与发布

- 普通 Go 程序，单实例、单进程提供页面、API 与后台任务。数据库使用 SQLite，数据文件独立于程序二进制；升级保留数据。
- 使用现代前端技术，构建后由 `go:embed` 内嵌 Go 二进制。按版本发版、统一打包发布。主要服务中国大陆访客。
- 前端候选为 React + TypeScript + Vite + Tailwind CSS + shadcn/ui；框架和 Go 库在实现时根据最终组件效果确认。
- 前后台共用布局、导航、偏好菜单、账号 / 登录 / 绑定弹窗、页脚和基础组件。页面各自提供内容和业务适配器。
- 固定规则与文案由代码维护；部署参数、数据库路径、会话密钥、QQ / OIDC / 易支付凭据和外部数据源配置使用环境变量，修改后重启。不提供通用在线配置中心。
- `legacy` 仅作为易支付逻辑、旧数据结构和旧站内容范围的参考，不继承其 PHP 实现或布局。

## 账号与权限

- 必须登录才能捐赠；QQ 或自定义 OIDC 任意一种均可。
- 两种身份分别首次登录时创建独立站内账号，不按昵称、头像或 QQ 号自动合并。以 OIDC `issuer + sub`、QQ 应用范围 OpenID 等稳定标识识别身份。
- 用户通过头像菜单进入账号信息弹窗，查看站内 ID 和 QQ / OIDC 的绑定资料；本人历史通过首页“只看我的”查看，不另建用户中心页面。
- 仅在已登录账号中绑定另一种身份，不允许解绑；若身份已属于其他账号则拒绝绑定，不提供账号合并。
- 当前昵称和头像使用本次登录提供方的资料，绑定操作不切换当前资料。第三方头像使用远程地址，不下载为本站持久化文件；公开历史随用户当前资料显示。绑定关系分别显示两种身份各自的头像、昵称与绑定状态。
- QQ 首次登录或绑定必须填写并校验 QQ 号后才能完成；仅 OIDC 用户不要求填写。QQ 昵称取官方 OAuth 资料。
- QQ 号与 OAuth 头像一致性检查参考私有项目 `TomyJan/ChinaNet-EDU-Login-Web` 的 `packages/server/src/services/oauth.service.ts`、`user.service.ts` 和 `utils/avatar.ts`，以 Go 重写。图片可在内存临时比较，不落头像文件；比较失败不能跳过检查。
- 头像比较不是强身份认证，相同 / 默认头像会造成误判，不能用于合并账号、认领旧订单或替代 OAuth 稳定标识。
- 管理员使用同一登录入口，环境变量 `ADMIN_USER_IDS` 指定站内账号 ID。菜单额外显示“站点管理”；页面和全部管理 API 均由服务端检查权限，不能以隐藏菜单代替鉴权。
- 封禁以站内账号为单位：撤销会话，禁止全部绑定身份登录和所有需登录的操作；解禁后需重新登录。每次受保护请求及登录 / 绑定完成前都检查封禁状态。历史订单保留，支付通知与对账继续如实处理。
- 登录采用同源 API、HttpOnly Cookie 与 SQLite 持久化会话，连续 30 天不活跃才过期；用户持续活跃就自动续期、持续保持登录，不设置固定强制重登的绝对期限。续期前重新检查会话撤销、过期及账号封禁，退出或封禁后不能被续期恢复；站内会话续期与第三方 OAuth Token 刷新分别处理。续期写入频率与凭证轮换属于实现参数，不改变活跃用户持续登录的规则。

## API 约定

- API 使用 `/api/v1` 前缀和语义化的模块 / 动作路径，例如 `GET /api/v1/user/profile`、`POST /api/v1/user/login`、`POST /api/v1/order/create`、`POST /api/v1/admin/order/reconcile`。不采用 RESTful 资源方法映射，业务只使用 GET / POST，不使用 PUT / PATCH / DELETE。
- GET 仅查询；创建、修改、退出、续期和管理动作使用 POST，使用 Cookie 的写操作需要 CSRF 防护。HTTP 协议层的必要处理不计作额外业务方法。
- 一般业务成功与失败均使用 HTTP 200，由稳定业务 `code` 区分，统一响应结构；登录无效和基础访问控制失败使用 401 / 403。HTTP 200 不代表业务成功，前端必须检查业务码。
- OAuth 跳转 / 回调、易支付通知与浏览器回跳遵循第三方协议，不强制包装成站内 JSON 响应，通知按协议返回确认文本；不记录授权回调的完整查询参数。

## 日志与可观测性

- 日志必须明确分级，覆盖启动 / 停止、配置校验、迁移、HTTP 请求、登录 / 绑定 / 会话续期与撤销、鉴权、订单创建、渠道交互、通知验签 / 校验 / 幂等更新、查单补单、超时关单、任务调度 / 重试 / 恢复、属地、管理操作、导出及异常。
- 控制台打印与文件保存的主要正文必须能独立说明发生了什么，并在语句中包含相关重要唯一标识，不能只写 `payment_callback_received` 等事件名后把信息全部放在附加字段中。结构化字段仍保留，便于检索和关联。
- 例如正文应表达“订单 {order_id} 的补单任务 {task_id} 第 {attempt} 次查询失败，请求 {request_id}，将在 {next_attempt_at} 重试”，并同步记录 `order_id`、`task_id`、`request_id`、渠道、状态与耗时等结构化属性。与订单无关的日志使用该流程的请求 / 用户 / 会话记录 ID 等必要标识，不强行填不存在的 ID。
- DEBUG 用于排障细节和无变更过程，INFO 用于正常生命周期与业务状态变更，WARN 用于校验异常、限流、可恢复故障及重试，ERROR 用于操作失败、重试耗尽、数据不一致或基础设施故障；同一错误不在各层重复报 ERROR。进程无法启动时明确记录原因并非零退出。
- 不把会话凭据当日志标识，使用独立会话记录 ID。不得记录 Cookie、OAuth code / state / Token、商户密钥、完整回调查询或认证头；不将完整请求 / 上游响应无选择写入日志。必要外部流水需按允许字段记录，用户输入须安全编码、防止伪造换行日志。
- 日志具有统一时间、级别、正文与关联字段；文件需要轮转、保留及写入失败处理，控制台与文件正文遵守同一规则。业务审计与运行日志分别维护，不因记录运行日志而保留被物理删除的订单内容副本。

## 捐赠与历史

- 留言选填，为订单内容的一部分，无独立留言模块。金额自由填写，最低 0.01 元、最高 100,000 元，包含上下限，最多两位小数。
- 快捷金额依次为 `0.01`、`8.88`、`20.26`、`50`、`128`、`256`、`648` 元，仅填入金额，不直接下单。
- 金额在输入阶段限制无效编辑，提交时前后端独立校验。金额用整数分存储和计算，不使用浮点数；渠道限额仍需接入验证。
- 易支付接入支付宝、微信，默认支付宝；支付选择与捐赠动作组成分体按钮。
- 支付平台为彩虹易支付；协议建议与已核对的 V1 / V2 差异见[接入方案](payment-integration.md)，实际商户能力在联调时验证。
- 未付款订单有效期为创建后 30 分钟，以服务端时间判断，过期可重新下单。本站过期不等于渠道关单；核实渠道查单 / 关单能力，正确接收实际到账通知。
- 异步通知验证签名、商户、订单、金额和状态，幂等落库后应答；浏览器回跳不作为支付成功凭证。
- 支付必须具备自动补单和管理员手动补单。补单是向渠道查询实际结果、校验后修复本地状态，不允许凭客户端参数或管理员按钮直接标记支付成功。
- 自动补单使用 SQLite 持久化任务队列，明确领取周期、首次查询时间、重试间隔、截止条件、并发和渠道限流；重启后恢复未完成任务。具体时间参数在后端设计中确定，不用内存定时器作为唯一任务记录。
- 订单详情提供“手动补单”操作，不新增页面或另做视觉方案，不增加批量补单。该动作与自动任务、通知共用校验及幂等状态更新；同一订单去重 / 协调并发，保留触发来源、操作者、任务与结果记录。
- 覆盖重复 / 乱序通知、查询与通知并发、签名或金额不匹配、渠道超时 / 限流、进程中断、本站过期 / 关闭后实际到账等情况。已支付不因后续未支付结果降级；已删除订单不补建。通知只在持久化成功或确认安全重复后按协议应答，失败不得虚假确认。
- 不提供退款或暂停捐赠开关。
- 公开历史只展示已支付、未隐藏、未删除的订单。游客由后端限制为最新 10 条，不能通过翻页或其他查询遍历更早记录；登录用户可分页查看更多。
- “只看我的”包含本人待支付、已支付、已关闭等订单；待支付可继续支付。隐藏数据对后台和本人仍可见。
- 记录真实下单 IP；仅信任连接地址或明确受信代理的转发头。属地异步查询，不阻塞下单、支付或通知；保存实际可用位置及来源、版本、查询时间。
- 公开 API 最多返回省级属地，不下发完整 IP、细位置、完整 QQ 号、OAuth 标识或原始数据源响应。后台鉴权后展示完整可用属地，不推断缺失字段。数据源方案见 [IP 属地](ip-geolocation.md)。

## 管理后台

- 固定四个页面：订单、用户、概览、审计。布局、详情、筛选和交互以最终 HTML 为基准。
- 订单支持昵称 / 用户 ID / 订单 ID 搜索，以及状态、支付渠道、公开范围、日期时间、金额筛选。各表通过表头排序，先排序再分页，无独立排序弹窗。
- 选择订单后，在原有标题操作位显示选择数量、取消、导出与批量菜单；未选择时不显示导出，不额外占一行。
- 操作包括导出、关闭未支付、隐藏 / 恢复订单、隐藏 / 恢复留言、删除。所有批量操作，包括导出，先展示范围与逐项订单再确认；执行时逐项校验权限和状态，返回具体结果。
- 关闭仅处理仍未支付的订单，其余显示实际状态及跳过原因；重复隐藏 / 恢复显示无需变更。正式关单须核验渠道状态。
- 订单列表与审计复用同一订单详情：金额、渠道、状态、完整 ID、用户、创建 / 支付时间、流水、留言、公开范围、IP 与完整可用属地。ID 可复制。
- 详情直接提供删除、导出、手动补单，仅待支付显示关闭；删除直接进入确认，无额外操作菜单。手动补单提供实际核验与修复结果，不保留无实际作用的示例查单按钮。
- 删除为物理删除，无软删除、回收站或分阶段删除。事务清理订单关联内容与任务；删除后退出公开列表、本人历史和统计。支付通知和异步任务不得重新创建已删除订单。
- 隐藏订单移除整条公开记录；隐藏留言只移除公开响应中的留言。两种状态独立且可恢复，均不影响后台统计。
- 概览默认最近 30 个上海自然日，可选今天、昨天、7d / 30d / 90d、全部及自定义区间（左闭右开）。到账、每日和渠道按支付时间，待支付 / 已关闭按创建时间；隐藏计入、删除排除。首页不展示任何统计。
- 用户详情以统一属性行显示状态、权限、最近登录，查看绑定资料、捐赠历史并支持封禁 / 解禁。管理员权限只读；定稿参考中禁止封禁当前管理员，实现沿用此保护。
- 审计记录操作者、时间、动作、目标 ID 和结果；目标关联现存订单 / 用户显示可读摘要与详情入口。列表不展示 ID；现存目标以可读昵称 / 金额直接打开共享详情，订单删除后仅显示删除状态，不保留订单内容副本或恢复功能。
- 导出范围为选择并确认的订单，金额使用整数分；不含完整 IP 或第三方认证标识，处理 CSV 引号和公式前缀。

## ID、数据与迁移

- 所有内部实体 ID 使用 UUID 类型，包括用户、订单、绑定、会话、后台任务及审计；不使用自增 ID，外键采用相同表示。界面统一称“ID”。
- 建议 Go 生成 UUIDv7，SQLite 用 16 字节 BLOB 并约束长度，对外使用标准字符串；明确保留时间字段，不以 ID 替代业务时间。
- OAuth state、会话凭据等认证随机值独立生成，不用 UUIDv7 代替不可预测凭据。
- 第三方 sub / OpenID、支付流水和旧站编号按原值另存。易支付商户订单号从站内 ID 编码或建立唯一映射，接入时验证字符与长度限制。
- 使用关系数据库事务、外键和唯一约束维护一致性；SQLite 启用 WAL 与适当写入协调，订单 / 任务持久化，采用一致性备份。
- 旧数据在正式投产时由用户安排导入，当前不做实际迁移。旧捐赠作为独立历史记录，保留原编号、金额、时间、状态、留言，按公开规则显示；不按手填 QQ 号自动归属新用户。

## CI 与发布工作流

- 正式前后端实现必须同时建立完整 CI，覆盖 PR、主分支更新与手动检查；发版复用同一检查入口，验证并发布同一提交，不使用其他提交的检查结果替代。
- 前端覆盖格式、lint、类型、单元 / 组件测试、依赖检查、生产构建及浏览器回归；浏览器检查中英文、深浅色、320px / 手机 / 桌面、共用组件、加载 / 错误 / 过期状态与定稿布局。
- 后端覆盖格式、静态检查、单元及 SQLite 集成测试、竞态检查、漏洞检查、数据库迁移、生成文件零漂移及内嵌前端后的完整程序构建与启动验证。
- 认证续期 / 凭证轮换 / 撤销与支付通知 / 自动补单 / 手动补单的幂等、并发、异常和中断恢复是关键测试范围。使用临时数据库和可控的 OAuth / 支付 / 属地测试服务，普通 CI 不依赖真实账号、真实支付或外部免费服务可用性。
- 工作流采用最小权限、固定工具版本、冻结依赖安装、合理超时 / 并发控制和失败诊断产物；按项目采用的生态配置依赖更新。覆盖率门禁基于关键行为制定，不能靠降低标准或无意义用例通过。
- 发布流程验证版本 / tag / 完整提交及二进制内嵌元数据，产物附校验和；保持按版本打包发布，不改成推送后自动部署生产。最终发布平台与入口参数在实现时确定。
- 参考相邻项目的前端产物共享 / 内嵌、同提交发版及前后端检查；本项目使用 SQLite 和单二进制，不引入 PostgreSQL 或强制容器部署。实际工作流见 `.github/workflows`，本机验证不等于 GitHub 托管执行结果。

## 已落地参数与外部联调

这些属于接入与运行参数，不改变已固定的界面方向：

- React / TypeScript / Vite 正式前端，共用布局和组件；Go 模块化单体、SQLite、持久化任务。具体依赖以锁文件为准。
- 留言框只在文本编辑时重新测量高度；恢复非空草稿时初始化一次。窗口缩放、主题 / 语言、收据翻页或其他组件变化不触发高度重算。始终预留一行，达到卡片上限后内部滚动。
- 后台在 1100px 以内使用横向导航，960px 以内将订单 / 用户 / 审计表格转为带字段标签的卡片，保留表头排序、选择和详情操作；筛选控件按可读宽度换行。共享头部、账号弹窗和基础控件不复制实现。
- 会话空闲 30 天、活动无总时限；前台有交互时每 5 分钟续期，普通续期不轮换随机凭证。
- 公开与本人列表每批 10 条，后台默认 20 条 / 最大 100 条；留言最多 500 个 Unicode 字符，批量最多 100 项。
- 队列每秒领取、租约 60 秒、每 30 秒到期扫描，商户流量每秒 1 次；补单时序和失败退避见后端设计。
- IP 随订单保存至物理删除；一致性备份每日及打开已有数据库前创建，最近 7 份。
- 真实 OIDC issuer / claims、QQ 应用和头像样本、易支付部署版本 / 限额 / 关单能力以及属地数据包授权仍需部署联调；未提供真实凭据时不假装已完成这些外部验收。
