# 彩虹易支付接入

支持 V2 RSA 协议和显式选择的 V1 MD5 协议，支付宝 / 微信共用订单与补单状态机。普通 CI 使用隔离测试网关；实际商户的限额、响应和关单能力需部署联调确认。

## 配置

| 配置 | 用途 |
| --- | --- |
| `EPAY_URL`、`EPAY_PID` | 网关基址和商户 ID；URL 留空关闭支付 |
| `EPAY_PROTOCOL=v2` | 默认 V2，填写商户私钥及平台公钥 |
| `EPAY_PRIVATE_KEY_FILE` / `EPAY_PRIVATE_KEY` | 私钥文件或 PEM / Base64 值，文件优先 |
| `EPAY_PUBLIC_KEY_FILE` / `EPAY_PUBLIC_KEY` | 平台公钥文件或 PEM / Base64 值，文件优先 |
| `EPAY_PROTOCOL=v1`、`EPAY_KEY` | 显式启用传统协议及商户 key |
| `EPAY_REDIRECT_HOSTS` | 额外 HTTPS 支付跳转域名，逗号分隔，无通配符；默认允许网关 |

通知地址：`https://站点域名/api/v1/payment/notify`；浏览器回跳：`https://站点域名/api/v1/payment/return`。地址由 `PUBLIC_URL` 生成，不取请求 Host。商品名称固定，不把昵称或留言发送为商品内容。

当前只加载一组网关 / 商户和对应密钥，没有历史凭据注册表。改变默认协议只影响新订单，但处理旧单仍须保留其协议所需凭据。改变网关 URL、PID 或旧单所需密钥会影响旧单查询 / 通知验证；切换前先核清未结束订单，并向平台确认凭据轮换方式，不假定能自动兼容旧单。

## 当前协议适配

| 项目 | V1 | V2 |
| --- | --- | --- |
| 下单 | 浏览器受控表单 POST `submit.php` | 服务端 POST `api.php?s=pay/create`，`method=jump` |
| 查单 | 服务端 GET `api.php?act=order` | POST `api.php?s=pay/query` |
| 关单 | 无标准入口 | POST `api.php?s=pay/close`，取决于通道支持 |
| 成功码 | `code=1` | `code=0` |
| 签名 | MD5，key 仅在服务端使用 | RSA PKCS#1 v1.5 + SHA-256，`sign_type=RSA` |
| 编码 | 表单 | 表单，不是 JSON 请求 |

V2 的 PHP 入口与文档 `/api/pay/*` 使用相同处理器，可避免依赖网关 URL 重写。支付渠道放 `type=alipay|wxpay`，不要与其他平台的 method / type 约定混用。网关金额为元的十进制字符串，站内存储及 API 使用整数分。

签名按名称 ASCII 排序，排除协议定义的签名 / 空值字段；值 `0` 不能丢弃。V2 成功响应及通知验证平台签名和 Unix 秒级时间戳，时间窗口为正负 300 秒。签名覆盖符合协议的新增标量字段，业务只读取所需字段；响应中的嵌套扩展字段不参与标量解析。通知拒绝重复参数；不要把它理解为响应 JSON 重复键检测保证。

未签名的错误、超时或不存在响应不能证明未付款。过期但签名有效的通知不直接入账，可唤醒查单取得新鲜结果。V1 查询没有响应签名，以配置的 HTTPS 网关为信任边界，仍严格核对商户、订单、金额、流水及渠道。

跳转仅接受受允许域名约束的 HTTPS URL，不执行任意上游 HTML，不支持仅返回扫码 / JSAPI 的结果。外部通道域名须由部署方核对后明确加入。所有出站请求验证 TLS；V1 查询 URL 中含 key，错误和日志不能输出完整 URL。

## 到账、回跳与关单

- 同一订单固定商户单号、渠道和协议；并发下单协调复用结果，超时先查原单，不换单号或自动切协议。
- 浏览器回跳后首页核验本站订单；失败可手动重试，回跳参数本身不证明到账。
- 通知、自动核验及管理员补单统一校验并幂等入账。paid 不降级，已删除订单不补建。
- 查单核对的是易支付账本；可修复平台已记录而本站漏通知的情况，不能保证实时直查支付宝 / 微信。
- V2 查询仅 `status=1` 为已支付；`0` 未付，`2/3/4` 分别为退款 / 冻结 / 预授权观察，不作为到账，也不开放本站退款。
- 本地订单 30 分钟到期，自动核验窗口 24 小时；管理员可单笔补单。查询错误不作最终未付证明。
- 本地关闭不保证远端支付页失效；仅经验证的成功关单响应才记录远端确认。关单后再核验，失败继续兜底；后续真实到账仍如实入账。

## 上线核对

使用实际部署分别验证支付宝和微信，记录网关版本、通道、日期与结果：

1. 创建、跳转、浏览器回跳、通知和查单的商户 / 订单 / 金额 / 签名正确。
2. 漏通知、查询超时、同单重试、重复及乱序通知、到期后到账不会重复下单或误入账。
3. 通道支持或不支持关单时，本站状态、远端确认和兜底查询均正确。
4. V2 code=0、timestamp、RSA 和 jump 响应与本部署一致；使用 V1 时确认 code=1 和 GET 查单。
5. 签名篡改、金额不符、未知状态与基础设施失败有明确拒绝和可关联日志。
