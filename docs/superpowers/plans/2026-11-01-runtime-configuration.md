# 运行配置、文件生命周期与 IP 库更新

> 使用 executing-plans 在 master 本地逐项实现，沿用用户要求独立完成、原子化签名提交，不推送；最终做一次独立审查。

## 规格与裁决

- 用户确认：必须有当前目录的 .env；模板中每个键必须在该文件中声明。空值与缺失不同，进程环境只覆盖值，不能补齐缺失键。
- 配置缺失、格式、读取权限、值校验失败时，输出无秘密的内置 .env.example，列出原因并退出。写模板失败也明确报错，绝不覆盖 .env。--version 不依赖配置。
- 配置项与示例来自同一个 schema；示例采用「变量一行，下一行缩进注释」，长注释适当换行。模板生成纳入现有生成漂移检查。
- APP_NAME 默认 donate，只允许小写英文字母与 -，以字母开头结尾，最多 63 字符。它用于运行文件标识和日志，不改站点捐赠对象名称。
- DATA_DIR 默认 data，数据库和锁文件分别为 data/[appname].db、data/[appname].lock。LOG_DIR 默认 data/logs，BACKUP_DIR 默认 data/backups；三者均可单独配置，相对启动目录。
- 每天分别写 [appname]_YYYY-MM-DD.log 与 .jsonl，前者与控制台同格式。每个文件最多 20 MiB，续卷追加 .2、.3；重启续写当日末卷，不覆盖历史，不压缩。按程序运行地日期分日。
- LOG_RETENTION_DAYS 默认 30，BACKUP_RETENTION_DAYS 默认 7；0 表示不自动清理。只清理当前 app 的合法命名文件，不能误删其他文件；备份继续使用 SQLite 一致性快照，恢复选定源仍受保护。
- XDB / MMDB 示例路径统一 data/ipdb/。未使用的路径明确留空；online / disabled 模式不加载或下载这些文件。
- GEO_UPDATE_DAYS 默认 7，0 关闭下载；每个本地库有独立下载 URL，空 URL 不更新。仅 local 模式执行。地址可含查询密钥，日志绝不记录完整 URL、认证内容或请求错误中的 URL。
- 支持直接 XDB / MMDB 及 gzip、tar.gz、zip 中的单一匹配库；下载大小、解压量、时间与重定向均有限制，不按压缩包路径解压到磁盘。
- 首次缺库且已开启相应下载时先获取并校验；已有可用库更新失败继续使用旧库。周期更新校验后原子替换并热重载，失效缓存但不自动重算订单；替换 / 重载失败保留或恢复旧库。纯本地查询开关不限制管理员显式配置的库下载，文档分清这两类外联。
- 不自动迁移用户现有文件或修改实际 .env / 数据库。升级文档说明旧数据迁移和新增配置补齐。

## 审查重点

1. 错误模板写入不能带出实际密钥、覆盖 .env 或沿符号链接破坏配置。
2. 按天清理只能删除当前 app 的目标格式，不依赖不可靠的文件 mtime，不删恢复源。
3. 单个日志通道失败必须保留控制台输出，另一通道成功不能错误清除降级状态。
4. Windows 读句柄、重命名失败、取消与关闭交错时不能丢旧库或出现半更新读取。
5. 进程环境优先、可空值、模式禁网、更新下载许可之间必须清楚且有直接回归测试。
