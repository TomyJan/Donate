# XDB 优先属地查询重构

> 执行方式：executing-plans，沿用用户要求在 master 本地开发；只在最终复核时请求独立审查，不推送、不发版。

## 已确认设计与边界

用户批准：XDB 优先，保留 MMDB，统一字段后按需在线交叉核验；异步执行、缓存、限流、故障转移、旧订单显式刷新继续生效。

- local 模式按 XDB → MMDB 收集候选；IPv4 / IPv6 的 XDB 分别配置，可只配一种，另一协议继续 MMDB / 显式允许的在线来源。online / disabled 保持原语义。
- 新增 GEO_XDB_IPV4、GEO_XDB_IPV6；GEO_DATABASE 继续兼容现有 City MMDB。文件路径以启动工作目录为准，不下载、不热更新、不打包真实地址数据。
- 只有 GEO_ONLINE_FALLBACK=true 的本地模式允许外发 IP；不完整候选继续故障转移，完整候选也可核验。最多取得两个完整在线候选；失败和缺字段仍按现有来源顺序回退。
- 统一国家、省份别名，比较省级归属；不跨来源拼接地理层级。XDB 是本地优先来源；冲突时采用明确的核验规则并记录依据，无法裁决不能覆盖旧有效快照。
- 记录选定来源、版本、核验状态和候选摘要；诊断只进入有权访问的订单详情，不进入公开捐赠列表。
- 无网络、缺文件、错误格式、版本不匹配、IPv6 缺库、未知占位符、来源冲突、缓存竞争、任务重试与旧数据兼容必须测试。

## 审查重点

1. 纯本地和 disabled 模式绝不外发 IP；缓存也不改变此边界。
2. 并发读取、关闭和失败初始化不能泄漏文件或产生竞态。
3. 国家、省份冲突不能被更多城市字段或简单多数票掩盖；细粒度位置与坐标属于同一来源。
4. 自动查询与管理员强制刷新交错时，旧查询不能覆盖新缓存或旧有效快照。
5. 数据库升级兼容老数据，公开接口不泄漏候选精细位置或查询诊断。

## 最终实现

- 固定官方 Go 读取器版本：`github.com/lionsoul2014/ip2region/binding/golang v0.0.0-20261028042204-6a276cc7c4f9`；IPv4、IPv6 独立文件，兼容官方 v3 和旧 v2 IPv4 字段布局。
- 读取器串行保护共享文件偏移；服务关闭幂等，初始化失败释放已打开的文件。校验文件头、协议、索引策略及分段 / 向量范围。
- 本地顺序为 XDB → MMDB；纯本地不联网。启用在线补充后，完整本地候选最多与两个完整在线候选核验。保留整份选定来源数据，不拼接省市和坐标。
- 统一国家与中国省份别名、清理无效占位符、拒绝非法坐标；未解决分歧保留旧快照并重试。缓存返回深复制，失败 / 部分 / 分歧使用短缓存，强制刷新继续隔离旧查询。
- 新增迁移 00006，将最近查询诊断保存到独立的 `order_location_checks` 表；失败不覆盖 `order_locations`。事务继续校验任务来源、状态、租约和过期时间，订单删除级联移除诊断。
- 管理员订单详情新增带展开动画的属地核验区，显示状态、时间、候选和来源版本；公开及本人接口均不返回候选诊断。API、TS 类型和 SQL 生成文件同步。

## 审查与实库验证

- 独立审查发现查询中途取消时，诊断保存沿用已取消上下文会导致任务提前进入 `failed/save_failed`。先补失败回归，再将最终保存改为有界 3 秒 `WithoutCancel` 上下文，保留 SQL 租约校验。复核确认恢复为 `ready/source_unavailable/attempts=1`。
- 下载官方 IPv4 / IPv6 实库进行独立冒烟，发现官方最后一个向量使用分段末尾的排他边界，严格范围检查误拒绝正常文件。双栈回归先见红；只归一化末尾的单个哨兵，保留其他范围与对齐检查，再补“非末尾哨兵”和“越过末尾两个分段”的双栈拒绝用例。独立增量复核通过。
- 真实文件查询 `223.5.5.5` 和 `2400:3200::1` 均返回 `xdb / 中国 / 浙江 / 杭州市`，版本分别为 `2026-10-28T04:21:41Z`、`2026-08-14T05:38:41Z`。这里只验证真实格式与读取兼容性，不作为精度评测。
- 最终独立审查没有重要未解决问题。真实库与验证产物只在忽略的 `.tools/xdb-verification` 中，不提交或打包数据库。
