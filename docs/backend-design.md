# 后端设计

本文记录[产品约束](requirements.md)对应的服务架构，正式 Go 服务、React 前端及 CI 已建立；最终界面以[设计规范](design/README.md)为准，配置与维护见[运行说明](operations.md)。

实现遵循已确认的 Go 单实例、SQLite、内嵌前端、QQ / OIDC、易支付、语义化 GET / POST API、活跃会话持续续期，以及日志和补单要求。下文记录实现采用的表结构、调度周期与默认限额；实际渠道兼容性仍需部署联调。

## 1. 程序与模块

采用模块化单体，一个程序处理 HTTP、静态页面与持久化任务，不引入 Redis、独立队列或微服务。

| 部分 | 建议与边界 |
| --- | --- |
| 前端 | React + TypeScript + Vite；Tailwind CSS 与 shadcn/ui / Radix 作为组件基础，按定稿覆盖视觉与动画，不套默认后台模板 |
| HTTP | 标准库 `net/http` + chi，仅负责协议、输入输出、鉴权及调用业务服务 |
| 数据 | `database/sql` + `modernc.org/sqlite`，sqlc 生成类型化查询，Goose 管理版本迁移；纯 Go SQLite 便于交叉编译 |
| 认证 | OIDC 使用成熟的发现 / JWT 验证库和 OAuth2 客户端；QQ 使用专用适配器，不自行实现 JWT 验签 |
| 日志 | `log/slog`，控制台文本与文件 JSON 输出；轮转组件负责文件大小 / 保留，不改变日志正文 |
| 契约 | OpenAPI 3.0.3 为 API 来源，生成 Go / TypeScript DTO；业务服务不依赖生成的 HTTP 模型 |
| 交付 | `go:embed` 内嵌前端产物，通过构建参数注入版本、完整提交、精确 tag 与构建时间 |

依赖在实现时选择受支持的补丁版本并固定；本机现有 Go 版本不直接决定发布工具链。若组件库无法达到定稿效果，替换内部实现，保留组件接口和视觉。

目录为 `cmd/donate`、`internal/{config,httpapi,auth,order,payment,jobs,geo,admin,observability,storage,webassets}`、`web` 和 `api`，迁移位于 `internal/storage/migrations`。用户与身份在 auth / admin，审计事务工具在 storage；以具体业务接口隔离支付、OAuth、属地与时钟。

HTTP handler 不直接修改订单状态。认证服务维护身份和会话；订单服务维护交易规则；支付服务验证渠道结果并统一应用；任务模块只领取、调度、重试。前后台共享布局、会话客户端、账号弹窗与基础组件，后台仅替换页面内容和数据适配器。

SQLite 启用 WAL、外键、5 秒 busy timeout 和 `synchronous=FULL`。写连接单通道串行、读连接小池；事务内不执行外部网络请求。进程持有数据目录锁，第二个实例拒绝启动。所有时间按 UTC 存储，界面日期及后台按日汇总使用 `Asia/Shanghai`；筛选以带时区的时间传入，采用左闭右开区间。

## 2. 数据与一致性

内部实体 ID 采用 UUIDv7，SQLite 存为长度受约束的 16 字节 BLOB，对外为标准 UUID 字符串，界面统一称 ID。随机会话凭据、OAuth state 等独立使用密码学安全随机数。金额全部使用整数分，CNY 范围为 1–10,000,000 分。

| 表 | 核心字段与约束 |
| --- | --- |
| `users` | ID、状态、公开身份 ID、创建 / 最近登录时间；公开资料通过身份关联，不复制到每笔订单 |
| `identities` | ID、用户 ID、provider、issuer / app 标识、subject、昵称、头像 URL、经检查的 QQ 号、资料更新时间；唯一 `(provider, issuer_or_app, subject)` 及 `(user_id, provider)` |
| `sessions` | ID、用户 / 本次登录身份 ID、凭据哈希、CSRF 校验值、浏览器谱系 / 可信发行序、创建 / 最近续期 / 到期 / 撤销时间；凭据哈希唯一，不保存原文 |
| `browser_families` | 浏览器谱系 ID、持久合并别名、当前会话 ID 及其发行序；保留失效水位，不能回退旧账号；独立事务计数器分配发行序，不作实体 ID |
| `auth_flows` | ID、意图、provider、state 哈希、nonce、临时 PKCE / OAuth 资料、绑定用户及会话 ID、阶段、到期 / 消费时间；一用即失效 |
| `orders` | ID、可空用户 ID、唯一商户订单号、金额分、渠道、留言、状态、关闭原因、创建 / 到期 / 支付 / 关闭时间、协议 / 商户配置标识、平台与支付渠道流水、最近观察状态 / 远端关单结果、两种隐藏标记、下单 IP、版本号 |
| `order_locations` | ID、唯一订单 ID、实际可用位置字段、来源 / 数据版本 / 查询时间；结果快照，不拼接不同源 |
| `jobs` | ID、类型、订单 ID、状态、到期执行时间、尝试次数、租约 token / 到期时间、触发来源 / 操作者、最近结果；每订单每任务类型只允许一条活动任务 |
| `task_events` / `task_recording` | 持久记录状态转换、领取 / 恢复、调度 / 重试及完成结果；与业务变更同事务，保留录制起点，升级前仅保存当前快照，不伪造历史 |
| `task_retry_requests` | 管理员作用域的重试幂等键、规范化任务集合摘要及逐项响应；同键重放不再次重排任务 |
| `payment_observations` | ID、订单 ID、来源、任务 / 请求关联 ID、渠道流水、经过校验的状态 / 金额 / 时间和应用结果；不保存完整回调或原始响应 |
| `admin_operations` / `admin_operation_items` | ID、管理员、动作、幂等键、请求摘要、开始 / 完成时间、逐项目标 ID 与执行结果；支持异步关单和批量结果查询 |
| `idempotency_records` | ID、调用者、动作、幂等键、参数摘要、目标 ID、完成结果 / 消费标记、过期时间；唯一 `(caller_id, action, key)`，删除目标后不保留其内容 |
| `audit_events` | ID、操作者、动作、目标类型 / ID、时间、结果和允许的技术元数据；不存订单内容快照 |

订单表允许 `user_id=NULL`，为最后投产时的旧数据导入预留，不允许客户端创建无主新订单；导入工具本阶段不实现。站内订单 ID 与网关流水分开。支付服务商、商户号等非秘密标识随订单保存，已有未结清订单时不允许直接切换商户配置后继续查询旧单。

关键约束包括金额范围、状态枚举、合法渠道、网关流水在商户范围内唯一、已支付订单必须有支付依据。支付去重键及数据库唯一冲突必须归到可判定结果，不能简单吞掉错误。

索引覆盖公开已支付列表 `(paid_at, id)`、本人历史 `(user_id, created_at, id)`、后台状态 / 渠道 / 创建时间、身份唯一键、会话哈希 / 到期、待执行任务 `(status, run_at)` 和审计时间。排序以 ID 作第二排序键，分页前排序；不允许客户端直接提供 SQL 列名。

删除订单在一个事务中删除订单、位置、支付观察和任务。审计及管理操作只保留目标 ID / 删除结果，已有逐项结果清除订单摘要；不保留留言、金额、IP 或可恢复的订单副本。旧请求的幂等键消费标记可短期保留，但不能保存订单内容或触发重建。正在执行的 worker 回写必须确认订单仍存在和租约有效，禁止 UPSERT 订单。

## 3. 认证、绑定与自动续期

### 登录和绑定

1. 前端通过 `POST /api/v1/user/login` 或 `identity/bind` 创建 10 分钟有效的授权流程，返回允许的授权 URL。state、nonce、PKCE 独立生成；绑定流程固定当前用户及会话，禁止回调参数指定另一个用户。
2. 回调验证 state、流程 Cookie、意图、有效期与一次性消费。OIDC 校验 issuer、audience、签名、到期和 nonce，以 `issuer + sub` 识别；QQ 以应用范围 OpenID 识别。只允许预设回调和站内返回地址。
3. QQ 首次登录 / 绑定进入号码检查阶段，号码仅接受 5–12 位且首位非零。按私有参考仓库的同尺寸头像比较逻辑以 Go 重写；网络失败允许在流程期限内重试，比较失败拒绝完成，每流程最多 5 次。阈值用样本验证后固定，不能伪称头像比较是强认证。已完成号码检查的 QQ 身份以后正常登录不重复填写。
4. 登录首次创建用户及身份；绑定只允许当前用户尚未绑定的 provider，身份已归属其他用户返回冲突，不合并、不开放用户自助解绑。管理员通过独立管理接口解绑，事务内检查目标身份属于该用户且至少还有另一种登录方式，撤销该身份会话和未完成绑定流程；如果移除公开展示身份，则改用剩余身份。最终事务再次检查封禁、身份唯一性和绑定会话仍有效；事务成功才创建正式会话 / 完成绑定。
5. 用户当前会话的昵称头像取本次登录身份。用户公开身份指向最近一次成功登录的身份，用于公开捐赠列表；绑定不切换二者。另一设备登录不会改写现有会话的身份指针。

OAuth 凭据只为当前流程短期使用；不请求 offline access，不持久保存 refresh token。必须暂存的 QQ token / PKCE verifier 使用部署密钥加密，流程完成 / 到期后清理。拉取头像仅在内存，限制固定可信域、体积、解码尺寸与超时，不接受用户提供任意 URL。普通退出仅退出本站，不注销 OIDC 提供方的其他站点会话。

### 会话

- Cookie 凭据为独立 32 字节随机值，仅保存 SHA-256 哈希；会话另有可用于日志的 ID。生产认证名为 `__Host-donate_session_<session-id>`；`Secure`、`HttpOnly`、`SameSite=Lax`、`Path=/`，不设置 Domain。后缀必须与 token 哈希查出的真实会话 ID 一致，不按客户端名称排序。本机 HTTP 开发使用 `donate_session_dev_<session-id>`。旧固定名凭据继续可用，首次有效请求迁至独立槽位并删除观测到的旧名；新服务不再向固定名发行认证凭据。
- 会话有效期 30 天，无绝对存活上限；仅剩余不超过 20 天时才续至当前时间 + 30 天。前端按到期窗口调度 `POST /api/v1/user/session/renew`，页面可见且近期有活动才触发；窗口外不轮询，无交互的后台标签页不靠定时器永久保活。
- 登录后的业务写操作成功时遵循同一窗口检查；窗口外不更新数据库到期时间、不重发会话 Cookie。前端同页去重、跨标签串行，并先核对服务端到期时间。GET 不承担续期，普通查询不修改业务数据；HTTP 缓存不能绕过会话校验。页面加载本身算活跃，单纯把页面闲置不算。
- 每次受保护请求读取会话与用户状态；不使用长时间的进程内权限缓存。续期事务以未撤销、未过期、用户未封禁为条件，不用过期凭据恢复会话。封禁事务同时撤销该用户全部会话；解禁不恢复旧会话。
- **续期延长有效期，不要求定期更换随机凭据。** 登录事务分配单调可信发行序，原子替换本浏览器谱系的当前会话并撤销旧会话；普通续期仍沿用原凭据，并只刷新自己的独立 Cookie 槽位。退出 / 自解绑只删除发起请求对应的精确槽位，不影响后到达浏览器的新登录。最新会话撤销、封禁、过期、删除或凭据缺失后均不回退上一个有效账号；解析和续期事务都检查持久 current，旧 token 不能换取新 token。
- 非认证锚点使用 `__Host-donate_browser_<family-id>`（开发为 `donate_browser_dev_<family-id>`），值为用途隔离 HMAC；锚点只关联谱系，单独携带不能登录。经 CSRF 与限流验证的 BeginFlow 才为匿名浏览器初始化谱系；普通匿名 site/info GET 不创建元数据。并发初始化各发不同名锚点，后续请求及 OAuth 发行事务合并验证过的谱系；别名持久指向 canonical root，迟到的旧锚点不能重新分叉。当前代际按服务端成功发行次序决定。
- 正常浏览器保持一个认证槽位和一个锚点。仅回收请求中已观察、确定旧或无效的精确名称。认证槽位或锚点分别超过 16 个时，本次请求返回 431 且不认证；最多处理 64 条观测元数据作清理，客户端重试时按剩余完整集合重新认证，绝不从截断集合选旧账号。每日会话 / 流程清理不删除谱系 current 和 alias 水位；首版保留少量 ID 元数据以避免旧凭据复活。
- 修改类请求采用会话绑定的 CSRF Token + Origin / Fetch Metadata 检查。匿名授权发起也使用流程 Cookie / CSRF；OAuth 回调按 state / nonce 验证而非普通 CSRF header。实际认证凭据不放 localStorage、URL 或日志。有效会话丢失必须明确要求重新登录，不偷偷创建身份。

## 4. API 契约与访问控制

统一业务响应示例：

```json
{"code":"OK","message":"","data":{"order_id":"..."},"request_id":"..."}
```

业务码为稳定字符串，前端按 code 和参数翻译文案，不匹配 message 文本。金额输入 API 使用整数分，拒绝浮点元；时间为 RFC 3339。返回 ID 不意味着有访问权限。

| 方法与路径（均为 `/api/v1` 前缀） | 权限 / 用途 |
| --- | --- |
| `GET /site/info` | 站点公开固定资料、版本、可用登录方式，不含部署秘密 |
| `POST /user/login`；`GET /user/oauth/callback/{provider}` | 发起授权 / 接收回调；回调转到站内固定完成页，不将凭据写进 URL |
| `GET /user/login/status`；`POST /user/login/qq/complete` | 流程 Cookie 保护的授权进度 / QQ 号码检查 |
| `GET /user/profile` | 当前用户、当前资料、双方绑定资料、管理员标记及 CSRF Token |
| `POST /user/session/renew`；`POST /user/logout` | 续期 / 当前会话退出 |
| `POST /user/identity/bind` | 登录后发起另一个身份绑定 |
| `GET /order/list` | 公开列表；有效登录可使用分页和 `only_mine` |
| `GET /order/detail` | 仅本人或管理员；公开读不提供任意订单详情枚举 |
| `POST /order/create`；`POST /order/payment/start` | 创建订单 / 获取同一订单支付跳转，必须登录且归本人 |
| `GET, POST /payment/notify`；`GET /payment/return` | 易支付协议入口；各参数只取协议指定位置，拒绝同名冲突参数，不混用通用 request 合并 |
| `GET /admin/order/list`、`/admin/order/detail` | 管理员筛选 / 排序 / 详情，返回完整允许字段 |
| `POST /admin/order/action/preview`、`/admin/order/action/execute` | 选择项确认、关闭 / 隐藏 / 恢复 / 删除 / 导出；不含批量补单 |
| `POST /admin/order/reconcile` | 单笔手动补单，返回任务 ID 或当前进行中的任务 |
| `GET /admin/operation/detail` | 查询执行进度及逐项状态；必须管理员，防止操作 ID 越权 |
| `GET /admin/user/list`、`/admin/user/detail` | 用户与绑定时间、捐赠金额；按字段白名单排序 |
| `POST /admin/user/identity/unbind` | 管理员确认后解绑用户指定身份；至少保留一种登录方式，撤销相关会话与绑定流程并审计 |
| `POST /admin/user/ban`、`/admin/user/unban` | 封禁 / 解禁；禁止封禁当前管理员 |
| `GET /admin/overview`、`/admin/audit/list` | 全部现存订单统计 / 审计；隐藏不排除，到账只算 paid |

一般业务失败使用 HTTP 200，如 `VALIDATION_FAILED`、`IDENTITY_CONFLICT`、`ORDER_NOT_PAYABLE`、`PAYMENT_PENDING`、`UPSTREAM_UNAVAILABLE`、`RATE_LIMITED`。缺失 / 无效登录为 401；封禁、非管理员、CSRF 拒绝为 403。服务器未处理异常为 500，服务尚未就绪为 503；代理自身的限流 / 请求体过大可按 HTTP 层处理。不存在的 API 路由可 404。前端统一处理业务码、401 / 403 和基础设施错误。

OAuth 跳转使用 302 / 303；支付通知按协议返回纯文本 `success` / `fail`，不套 JSON。CSV 导出成功为附件，失败仍返回业务 JSON；前端先检查响应类型。站内 JSON 错误不带 SQL、堆栈或上游原文。

匿名列表始终强制最新 10 条，忽略 / 拒绝突破范围的 cursor、页数或 limit；`only_mine` 无会话返回 401。公开 DTO 独立生成，不包含 IP、细属地、QQ、OpenID / sub、商户配置。经所有权校验的本人订单详情包含该订单的下单 IP；细属地及任务记录仍由后台详情提供。管理员通过普通详情查看他人订单也不额外取得 IP。

建议正式列表每批 10 条、后台默认 20 条 / 最大 100 条，留言最多 500 个 Unicode 字符且限制请求字节数；默认批量最多 100 个 ID。公开与本人历史使用稳定游标，后台表格使用排序 / 页码；变更后刷新当前页，允许提示数据已变化，不承诺跨请求数据库快照。预览 HTML 的样例分页数不作为协议。

POST 创建、管理执行与手动补单接受幂等键：绑定调用者、动作和规范化参数摘要，相同键不同参数报冲突。创建键由前端在一次提交期间复用，至少保存 24 小时；响应丢失重试不得重复建单。删除后重放旧键返回目标已不存在，不创建替代订单。

确认预览返回短期令牌，绑定管理员、动作和精确的去重 ID 集合，5 分钟过期；执行仍重新验证当前权限 / 状态。批量允许部分成功，逐项显示“已支付，跳过”“已关闭，跳过”等真实状态，不把预览当作执行承诺。导出只导出实际确认且仍存在的选择项，CSV 金额为整数分，正确转义并防公式注入。

## 5. 支付、通知与补单

### 易支付协议边界

支付平台已确认为彩虹易支付。采用 V2（RSA-SHA256）优先、V1（MD5）显式兼容，接口、证据与适配规则见[彩虹易支付接入方案](payment-integration.md)。旧版 `legacy:paycon/Core/Pay.Class.php` 仅接入传统跳转和验签，但 V1 协议本身有查单接口；不能把旧站没写查单误认为平台没有。新适配器不继承 PHP 的宽松过滤和浏览器回跳改状态。

默认保留站内订单 ID，把去横杠的 UUID 编码为商户单号候选，长度 / 字符集通过网关验证后固定。签名串由适配器专用代码生成；比较签名使用常量时间算法，回调请求体限 16 KiB。上游只访问部署中固定 HTTPS 域名、验证 TLS、不跟随任意重定向。回调地址使用 `PUBLIC_URL`，不相信请求 Host。

**可靠查单是投产前置条件。** V1 / V2 均已找到查询协议，但实际商户的权限、响应及通道仍需联调。所查实现返回易支付平台的账本状态，不保证每次实时直查支付宝 / 微信；补单修复易支付已记录而本站漏记的结果。关单能力取决于插件，不能仅凭 V2 就认定可用。协议验证使用文档及测试商户 / 沙箱，不在普通 CI 使用真实交易。

### 下单与跳转

创建事务校验会话、金额、渠道、留言，写入订单、属地任务和首次查单任务，再返回订单 ID。订单有效期从本地创建起 30 分钟，不因继续支付延期。`payment/start` 再次校验所有权、封禁、状态和到期；先持久化“可能已提交”标记，在事务外调用 V2 创建接口取得并验签跳转结果；V1 使用受控表单 POST 跳转。创建请求并发 / 超时处理按接入方案协调，避免用户已跳出但进程不知道。

同一订单始终使用原商户单号和渠道，不在超时后换号或换渠道重发。订单生成后要换渠道需重新下单。提交 / 查询超时是未知结果，不是未支付。浏览器回跳只显示“核实中”并读取本站状态，可把已有任务提前，不直接改为 paid；未登录时先恢复登录再访问本人详情。

### 唯一的支付状态应用入口

通知、自动查询、管理员补单都生成经过验证的 `PaymentObservation`，调用同一个事务入口。验证内容为适配器签名 / 查询凭据、商户、商户单号、金额分、CNY 语义、支付状态、渠道及网关交易唯一性。流水、金额或商户不符时隔离为异常，记录告警，不改到账。

| 当前本站状态 | 渠道结果 | 本站处理 |
| --- | --- | --- |
| pending | 已支付 | 原子写 paid、流水及支付时间，完成查单 / 关闭任务 |
| pending | 未支付 / 不存在 / 未知 | 保持，按计划查单；不存在不等于已关闭 |
| pending | 管理员关闭任务开始 | 持久化 closed 与原因，保留支付核验；远端失败不恢复本站入口 |
| closed | 远端关单 ACK | 保存确认结果，再查询一次支付状态；查询失败继续持久化重试 |
| closed | 经过完整校验的已支付 | 写 paid，记录迟到支付与原关闭原因，计入到账 |
| paid | 相同已支付结果 | 幂等确认，不重复计入、重写支付时间或生成重复业务事件 |
| paid | 未支付 / 关闭 / 未知 | 不降级，记录冲突并按严重度告警 |
| 订单不存在 | 任何结果 | 不创建订单、不恢复已删除记录 |

本地状态只有 pending / paid / closed；网关状态与本地关闭原因分开保存。“本地过期”不是“网关已关”。支付时间优先使用经过验证的渠道时间，缺失时用首次确认到账时间并记录来源，不以回跳时间伪造。

事务重新读取订单，用唯一约束和条件更新处理通知 / 查询并发；支付观察、状态、审计和任务结果一起提交。只有事务提交成功，或确认已持久化且内容一致的重复成功通知，才能回应 `success`。校验失败、未知 / 已删除订单或数据库故障回应协议 `fail`；数据库故障可用 5xx 促进重试。未知通知只记录受限技术信息并限流，不能虚假应答到账成功。

### 自动补单建议时序

任务保存在 SQLite，每 30 秒扫描到期项；启动立即扫描。默认支付查询最多 2 并发、每商户每秒 1 次；渠道要求更低时下调。查询单次总超时 8 秒，任务租约 60 秒，调用结束前检查租约；租约 token 条件回写，旧 worker 不得覆盖新任务。外部查询可重复，状态应用必须幂等。

| 时段 / 触发 | 建议调度 |
| --- | --- |
| 正常待支付 | 创建后第 1、3、8、18 分钟查询；约第 30 分钟最终查询，到期节点不被退避推迟 |
| 查询网络失败 / 限流 | 按约 1、2、5、10 分钟退避并加抖动，尊重 Retry-After；不当作未付款 |
| 本地到期且未确认到账 | 立即禁止继续支付，最终查询 / 关单任务继续；局部服务故障不延长订单支付入口 |
| 已到期 / 本地关闭但网关未确认关闭 | 创建后第 1、2、6、12、24 小时兜底查询；24 小时后停止自动轮询，保留异常结果与告警 |
| 已付或网关确认关闭 | 结束轮询；对现存订单仍处理后续有效通知，已付不降级 |
| 管理员手动补单 | 不受 24 小时自动窗口限制，立即提前 / 唤醒同订单任务，遵守商户限流；不新开并发查同一单 |

所有轮询受实际执行时间、限流与故障影响，不承诺精确到秒。对未确认关闭的订单，有限轮询不能保证无限期发现迟到支付；24 小时以后的有效通知仍可入账，管理员也可补单。停止自动轮询是成本上限，不代表渠道证明未支付；后台明确保留最近核验时间 / 结果。

同订单同任务类型只保留一个活动任务，领取采用短事务条件更新。租约期间手动触发记录一次待再次核验标记；运行完成后必要时立即重跑，不丢请求。任务及手动触发结果通过管理操作查询返回，前端可短轮询至完成。已支付订单手动补单可核实一致性，但不改变既有到账依据；已删除返回不存在。

渠道连续失败使用商户级熔断，降低无效请求，保留任务、告警和下次探测时间；恢复后分批消化积压，不一口气重放全部。24 小时窗口内若一直未取得有效核验结果，停止后必须记录 ERROR，后台可看到核验失败，不能显示为核验成功。

### 关闭与删除

管理员关闭先提交异步操作，每项获取订单级任务协调，然后查渠道；已付先入账并返回“已支付，跳过”。支持关单的通道执行关单后再核对，独立保存远端关单应答，超时保留“关闭处理中 / 待核验”，不伪称已关。彩虹所查查询状态没有 closed 枚举，不能把 `status=0` 当作已关，也不能要求关单成功后一定查到 closed。没有远端关单接口时，查询确认当前未付后只关闭本站支付入口，明确返回“本站已关闭，远端未确认”，继续迟到支付兜底。

到期处理先通过条件事务将仍为 pending 的订单记为 closed、原因为 expired，再执行最终渠道核验；无需等待查询成功就停止本站继续支付。`payment/start` 也独立检查到期时间，不能在调度间隔中继续支付。查询或关单失败不能恢复入口。有些网关旧支付页仍可付，本站不能凭隐藏按钮保证远端失效，所以任何现存本地 closed 订单收到有效到账都转 paid。关闭请求与到账竞态按实际支付结果收敛。

物理删除不调用退款，不保证终止已打开的远端支付页。确认界面说明删除后无法自动补记该单，建议先关闭未支付订单；用户仍可确认直接删除，不增加阶段或强制前置步骤。删除事务使后续任务、通知无法复建；在途查询结束只报告目标已删除。

## 6. 属地、日志与审计

IP 默认取连接地址；配置 `REAL_IP_HEADER` 后只读取指定请求头，合法的逗号分隔 IP 列表取首项。反代必须覆盖该头并限制源站直连。缺失、重复、格式异常或超长链均回退连接 IP；地址归一化为 IPv4 / IPv6。只保存下单 IP，通知来源不能覆盖它；私网等地址不发往在线服务。

属地使用独立任务和 worker，不阻塞支付，队列、缓存、故障转移按 [IP 属地方案](ip-geolocation.md)。默认先实现既定免密钥在线适配链，同时隔离本地 reader 接口；部署选择本地模式后无需在线发送 IP，数据包和授权另行确定。后台返回实际可用细字段；公开 DTO 最多省级，不能通过传 `fields` 获得后台信息。

运行日志正文和结构化属性都提供标识，控制台与文件保持相同语义。例如：

```text
INFO 订单 {order_id} 已由通知 {request_id} 确认为已支付，渠道流水 {trade_no}，金额 {amount_fen} 分
WARN 订单 {order_id} 的补单任务 {task_id} 第 {attempt} 次查询超时，将于 {next_at} 重试
INFO 用户 {user_id} 的会话 {session_id} 已续期至 {expires_at}，请求 {request_id}
ERROR 订单 {order_id} 的通知 {request_id} 金额不符：本地 {expected_fen} 分、渠道 {actual_fen} 分，拒绝入账
```

| 等级 | 使用边界 |
| --- | --- |
| DEBUG | 调度空扫描、未变化的重复结果、脱敏后诊断；默认关闭 |
| INFO | 启停、迁移、请求完成、登录绑定、有效续期、订单和任务状态改变、管理结果 |
| WARN | 验签失败、权限异常、可恢复超时、重试、限流、熔断、迟到支付 |
| ERROR | 请求无法完成、重试耗尽、存储 / 日志故障、数据矛盾、异常无法核验；启动失败记录后非零退出 |

请求 ID 由服务端生成；必要的上游追踪值另列且限制长度。任务有自己的 ID 并关联来源请求 / 操作者；同一个失败由负责恢复的层记录，避免一件事打印数条 ERROR。HTTP 200 的业务失败在日志中包含业务码和语义，不能只按状态码判为成功。

覆盖配置校验、迁移、启动 / 停止、请求耗时 / 结果、身份流程、会话 / 封禁、创建 / 跳转、通知校验与持久化、自动 / 手动补单、关闭、任务领取 / 租约恢复 / 重试、属地源切换、导出 / 删除及后台操作。请求日志仅记录路由模板、允许字段与必要标识，不记录原始 query、body、Cookie、认证头、OAuth code / state / token、商户密钥。昵称 / 留言不拼入正文；错误和用户输入安全编码、截断，不允许伪造换行日志。

`LOG_OUTPUTS` 选择 `console`、`log`、`jsonl`，逗号分隔，默认全部，至少一项；只初始化选中的输出。文件默认在 `data/logs/`，文本 `.log` 与控制台同格式，`.jsonl` 保存 JSON。按运行地日期新建，每卷 20 MiB，续卷追加 `.2`、`.3`；默认保留 30 天，可关闭清理。只清理已启用格式、当前 `APP_NAME` 的日志。启用的文件初始化失败则拒绝启动；运行中失败向 stderr 告警并标记就绪降级，其他输出继续。JSON 保留完整中文 `msg`。

操作审计写 SQLite，和管理状态变更同事务；失败操作记录失败结果。审计目标显示当前关联实体的可读摘要，不保存快照。运行日志允许记录订单 / 用户 / 任务 ID、金额校验信息等排障字段，但不保存整条订单、留言、完整 IP 或头像副本。物理删除清理业务表中的订单内容，日志不是订单恢复渠道。

## 7. 配置、运行与备份

环境变量按用途分组并在启动一次性验证，文档和 `.env.example` 只给占位值：

- HTTP / 数据：`APP_NAME`、`LISTEN_ADDR`、`PUBLIC_URL`、`DATA_DIR`、`BACKUP_DIR`、`BACKUP_RETENTION_DAYS`、`REAL_IP_HEADER`。数据库与锁默认 `data/APP_NAME.db` / `.lock`。
- 权限 / 认证：`ADMIN_USER_IDS`、短期流程加密密钥、OIDC issuer / client ID / secret、QQ app ID / secret。
- 支付：固定网关 URL、商户 ID、`EPAY_PROTOCOL=v2|v1`、V2 商户私钥 / 平台公钥或 V1 key、允许的跳转域名与限流值；不能用一个布尔值谎报关单能力。
- 属地 / 日志：本地库默认 `data/ipdb/`，可配置下载 URL / 更新天数、在线补充及日志等级 / 目录 / 保留天数。下载验证、原子替换与热重载不改变旧订单。

`.env` 必须存在且声明模板每个键；可选值可为空，进程环境变量覆盖值。缺文件、缺键、格式或读取错误时生成不含实际密钥的 `.env.example` 后退出，`--version` 免配置。示例由配置 schema 生成，并检查生成漂移。

新增管理员先正常登录取得站内 ID，再配置环境变量并重启；不放置默认管理账号或后门。静态资源和带哈希文件可缓存，API / 授权回调及用户内容禁止共享缓存。默认不开放跨域 API，页面设置合适 CSP、点击劫持和 MIME 防护；回调参数、配置文件、数据目录不作为静态资源提供。

默认单用户每分钟最多创建 5 单、最多 10 个有效待支付订单；登录发起 / QQ 检查、管理危险动作和补单另做有界限流。IP 限流要兼顾校园网 / NAT，不能代替用户级限制；具体阈值可在实现压测后调整。

启动先验证配置、获取实例锁、备份迁移前数据库、执行事务迁移，再开放就绪和 worker。迁移失败不对外提供业务。提供不含敏感信息的存活 / 就绪端点，数据库不可用时就绪失败；日志文件异常有明确降级结果，不把进程存活当作全部正常。

收到退出信号后停止接新任务 / 请求，限时排空 HTTP 和在途事务；无法完成的任务由持久化租约恢复。数据库备份采用 SQLite 一致性备份接口，不在 WAL 活跃时只拷贝主文件；每日及迁移前备份默认在 data/backups/，按 UTC 快照时间保留 7 天，可配置，0 不清理，部署方保存异机副本。完整 IP 随订单保存至物理删除，默认不单独自动删减；备份到期淘汰，不声称在线删除能立即抹除历史备份。演练恢复时停机、校验迁移版本与完整性，并防止旧会话 / 已删除订单因恢复备份被误认为最新状态。

## 8. CI、发布与验收

参考相邻项目的做法，但检查必须服务 Donate 自身。`code-check.yml` 覆盖 PR、master 和手动运行，作为 reusable workflow 供 release 调用；最小权限、固定工具 / Action 版本、冻结锁文件、超时和并发取消，失败保留日志 / 浏览器 trace。不把其他仓库的 PostgreSQL 或部署方式带入。

| 检查 | 内容 |
| --- | --- |
| 前端 | 格式、lint、TypeScript、关键组件 / 业务单测、依赖风险、生产构建；依赖有受影响漏洞就处理或提供有期限的明确例外 |
| 后端 | gofmt 零差异、go vet / 静态检查、单元与 SQLite 集成、`go test -race`、govulncheck、迁移从空库 / 上版升级 / 失败回滚 |
| 生成 | OpenAPI 校验、Go / TS DTO 和 sqlc 重新生成后零差异；前端构建并作为同一提交产物交给 Go embed |
| 浏览器 | 对最终二进制运行 Playwright；覆盖中英文、深浅色、320px / 手机 / 桌面、键盘 / 减少动态效果、账号共用组件和后台操作 |
| 包与启动 | Linux / Windows 的数据库与路径烟测；内嵌页面、API fallback 边界、版本命令、就绪 / 退出、无 Node 运行时也可启动 |

关键验收不能靠接口快照代替行为测试：

- 会话活跃跨越 30 天继续可用、连续空闲到期、普通续期不强制重登；多标签页并发续期，封禁 / 退出与续期竞态、重启后撤销保持。
- OAuth state 重放 / 错绑、QQ 检查失败、身份并发绑定、已归属其他用户、封禁用户不能经另一身份登录。
- 通知重复 / 乱序、通知和查询并发、金额 / 商户 / 签名 / 流水冲突、提交后应答前崩溃、数据库提交失败不 ACK。
- 查询超时 / 限流 / 熔断、租约过期和重启、手动与自动合并、关闭时已到账、到期后到账、删除与在途任务 / 回调竞争；paid 永不降级，删除不复建。
- 游客无法绕过 10 条、隐藏数据不泄漏、本人 / 非管理员越权、公开 DTO 不含 IP 或认证标识、CSV 选择范围和公式防护。
- 控制台及落盘日志正文有关键标识，日志内容不泄露测试凭据，轮转 / 磁盘失败有可验证行为；审计删除后无订单副本。

测试使用临时 SQLite、可控时钟、虚拟 OAuth / 网关 / 属地服务和故障注入，普通 CI 不依赖第三方账号、免费接口在线或真实扣款。支付与会话关键分支设置覆盖门禁；具体全仓覆盖率在代码建立后确定，不用无意义用例凑数字。

发布采用手动入口输入语义化版本，检查工作区 / 版本 / tag 冲突，固定完整提交并通过同提交检查后打包；发布 job 禁止自动取消。建议首批 Linux amd64 / arm64、Windows amd64，附 SHA-256 校验和、许可证与升级说明。tag 指向验证提交，二进制 `--version` 与内嵌前端版本必须一致。

恰在发布 tag 上显示 `V0.0.1` 并整体链接 tag；其他构建显示 `V0.0.1-aabbccd` 并整体链接完整 commit。正式发布不打包 dirty checkout；编译脚本验证精确 tag，不能仅凭环境变量把任意提交冒充版本。发布不自动部署生产，也不把每次 master 更新变成正式 release。

## 9. 接入前需要核验的外部条件

这些不需要重新选择产品方向，但必须在对应功能完成前拿到证据：

1. 彩虹 V1 / V2 的公开协议与所查实现已记录在[接入方案](payment-integration.md)；实际商户部署支持的协议、通道、额度和关单结果仍需联调，不需要用户再寻找通用文档。
2. OIDC 的 issuer、claims 与 QQ 应用回调设置；QQ 头像检查用私有参考实现及样本校准，不凭空承诺强身份验证。
3. 免费属地接口当前额度 / 授权，或本地数据包选择及样本验证。先保持既定在线实现基线，不默认采购 MaxMind 或其他付费库。

正式实现保持最终页面结构，补齐真实接口和已确认的手动补单操作。OpenAPI 从实际 Go JSON DTO 推导，再生成 TypeScript 类型；sqlc 生成固定查询，动态筛选使用参数化 SQL 与排序白名单。工作流通过重新生成比较来检查漂移。
