# 最终界面与交互设计

本目录固定 Donate 的收据册首页与管理工作区，作为正式实现的视觉和交互基准。仅保存这一套最终方案。参考页全部使用示例账号和订单，不连接真实 OAuth、易支付或数据库。

## 交付与运行

| 内容 | 位置 |
| --- | --- |
| 首页 HTML | [preview/index.html](preview/index.html) |
| 后台 HTML | [preview/admin.html](preview/admin.html) |
| 共用布局与基础组件 | `src/shared/shell.js`、`shell.css` |
| 首页结构、样式与控制器 | `src/pages/home.html`、`home.css`、`home.js` |
| 后台结构、样式与控制器 | `src/pages/admin.html`、`admin.css`、`admin.js` |
| Logo 快照、独立预览画布 | `src/shared/logo.js`、`preview.css` |
| 固定图标依赖与授权 | [vendor](vendor/README.md) |
| 生成与本地服务 | `build.py`、`serve.py` |

在仓库根目录执行 `python docs/design/serve.py`，打开首页 `/` 与后台 `/admin`；`--port 52772` 可指定端口。只绑定本机地址，不提供生产服务。HTML 可直接打开，字体需要访问 MoeCDN；本地图标和 Logo 不依赖外部预览环境。

源码修改后运行 `python docs/design/build.py`，再用 `python docs/design/build.py --check` 检查两份 HTML 与源码一致。不要直接修改生成的 HTML。生成结果不随本机路径、时间或 Git 提交变化，便于核对。

## 共用布局与视觉

- 全站使用纸色背景、简短文案、疏朗留白；前后台共用颜色、导航、菜单、账号弹窗、登录与绑定流程、页脚及按钮 / 头像 / 对话框骨架。
- 导航桌面高 104px、窄屏高 90px。左侧 Logo + 同样式整段文字“捐赠 TomyJan”，Logo 使用 `https://public-cdn.tomys.top/head.png`，圆角 35%；后台仅增加站点管理位置标签。
- 右侧依次是语言、主题、昵称头像按钮；窄屏隐藏昵称，保留头像。悬停、键盘聚焦和展开状态显示统一的圆角填充及轮廓。管理员菜单包含账号信息、站点管理、退出登录。
- 控件圆角 9px，菜单 / 弹窗外框 14px。菜单项目有间隔，选中与聚焦采用内缩背景；下箭头展开、收起都有过渡。
- 全站 MiSans；仅首页金额输入及收据大卡金额使用 Source Code Pro 700。快捷金额、列表金额、所有弹窗金额及后台金额均用 MiSans。Source Code Pro 当前线上样式只声明 400，700 由浏览器合成加粗。
- 字体源：`https://cdn.amoe.cc/web-static/public/font/misans/misans.css` 与 `https://cdn.amoe.cc/web-static/public/font/sourcecodepro/sourcecodepro.css`。加载后重新测量内容高度。
- 简体中文 / English；跟随系统 / 浅色 / 深色。分别使用语言标记和 Monitor / Sun / Moon 图标，选中项显示 Check。
- 页脚居左、普通文本，`Donate` 与版本仅隔一个空格。正式发布恰在 tag 上时整个 `V0.0.1` 链接 tag，否则整个 `V0.0.1-aabbccd` 链接完整提交。Go 发版构建注入元数据。独立静态 HTML 使用可解析的分支示例 `V0.0.1-master`；本地服务替换为当前 Git 提交 / tag，未发布时的 `0.0.1` 仅为示例版本。

## 收据册首页

只包含导航、捐赠入口、捐赠记录与页脚，不加统计、宣传段落或装饰性箭头。桌面左右两栏，左侧可填写票据、右侧收据叠层和索引；手机单栏，填写票据默认收起，点击“捐赠”原位展开。

金额、快捷选择、留言和支付按钮等宽。七个快捷金额宽卡一行，窄卡四个 / 三个两行，均匀铺满。金额聚焦轮廓包住人民币符号；留言输入面无圆角，仅底线高亮且两端圆润。

金额仅接受普通十进制和两位小数，范围 0.01–100,000 元；拒绝字母、指数、正负号、逗号、第三位小数和超额编辑，保留选区及光标。空值、`0`、`0.` 是允许的编辑中间态，但支付按钮背景与文字均灰显禁用。留言支持多行、自动增高并预留一行；达到右侧内容高度预算后内部滚动，避免输入票据无限拉长。

支付采用分体按钮，默认“捐赠 · 支付宝”，右侧箭头选择微信；切换只改变渠道，不触发支付。游客发起捐赠先登录，登录后保留原金额、留言与渠道继续。

收据按实际内容自然增高，无留言时收紧。标题右侧是“只看我的”高亮切换按钮，最右为翻页箭头；索引可直达记录。公开索引左侧为名称与灰字日期时间，例如“小林 10.29 14:26”；本人历史左侧直接显示“10.29 14:30”，不拆分或重复日期。本人已支付订单不重复标状态，待支付 / 已关闭仍显示，详情和继续支付位于大卡金额右侧。

游客底部显示“登录后可查看更多”；登录后显示“更多”，全部展示后为“没有更多了”。参考页面按示例数量分批展示；正式公开权限和分页由服务端执行。

## 账号与身份

账号使用共用弹窗，当前昵称下方直接显示站内 ID，不重复展示提供方或绑定说明。QQ / OIDC 分别显示资料与绑定状态；操作列固定 76px、居中对齐，已绑定不显示解绑。

登录可选 QQ 或 OIDC；QQ 需填写号码，输入阶段限制数字及位数。参考页面仅检查格式，真实号码与 OAuth 身份校验按 [实现规格](../requirements.md) 接入。“只看我的”承载本人捐赠历史，不另外设计用户中心页面。

默认演示身份为管理员；身份、绑定、语言、主题通过本地存储在同源页面 / 标签页同步，存储不可用时仍能在当前页演示。退出后后台显示登录状态，普通用户显示无权限。这些是演示状态，不能用作生产鉴权。只保存预览偏好和绑定布尔值，不保存 QQ 输入号码或凭据。

## 管理工作区

后台使用平直账簿布局；桌面侧栏、窄屏顶部导航。页面为订单、用户、概览、审计。

- **订单**：搜索、状态 / 渠道 / 可见性筛选，展开日期时间与金额筛选；先排序完整结果再分页。选中后，数量、取消选择、导出和批量操作出现在标题右侧，不新增工具栏高度。未选中不显示导出。
- **批量操作**：导出、关闭未支付、隐藏 / 恢复订单、隐藏 / 恢复留言、删除。全部先确认范围和明细；不适用项显示“已支付，跳过”等具体原因；重复操作显示无需变更。列表末项无底部分隔线。确认危险操作使用独立且适配深色的颜色。
- **订单详情**：订单表和审计共用 `orderDetailView` / `orderDetail`。金额、渠道与状态、完整 ID、用户与时间 / 流水、留言、公开范围、来源信息依次排列。直接显示删除和导出，待支付才显示关闭；删除直接确认，无多余子菜单和查单按钮。由订单进入用户可返回原订单。
- **属地**：后台展示数据源实际可用的国家、省、市、区县 / 街道、运营商、ASN、坐标 / 精度范围及来源 / 版本。缺字段就省略，不补造数据，不加公开省级范围说明。参考 IP 和细位置为合成示例，不是真实定位。
- **用户**：搜索与封禁筛选；身份资料和绑定列表复用共用组件，状态 / 权限 / 最近登录采用相同属性行；可进入历史、封禁或解禁，禁止封禁当前管理员。
- **概览**：到账、订单状态、每日和渠道汇总；隐藏不影响统计，物理删除退出统计，待支付 / 关闭不计到账。
- **审计**：操作时间、操作者、动作、目标摘要及 ID；现存目标可进入同一份详情，删除后只显示删除状态与 ID，无订单副本。

所有表从表头排序，无独立排序方式按钮。下拉框为自绘列表，保留箭头右侧间距；日期时间使用自绘月历，支持年月、小时 / 分钟、清空 / 应用。详情窄屏正文滚动，操作区换行，长 ID 和文本可折行。

正式实现按 [实现规格](../requirements.md) 在订单详情操作区增加“手动补单”，核实渠道结果并修复本地状态；这是一项已确认的小操作补充，不另做布局方案。冻结 HTML 保留视觉基准，尚未模拟补单后端行为。

通知独立堆叠，不挤占正文；最多四条，有进出及队列位移动画，支持关闭、超时消失、悬停 / 聚焦暂停。成功用状态播报，错误用警报语义。

## 动效与键盘

| 交互 | 最终表现 |
| --- | --- |
| 收据翻阅 | 旧纸按方向抽离，新纸落位，背景叠层不动；抽离 220ms，落位与高度 320ms |
| 共用菜单 | 位移与透明度展开约 200ms、收起 130ms，不缩放文字，静态终态一致 |
| 弹窗 / 抽屉 | 遮罩淡入，弹窗上移或详情侧向进入，关闭反向退出 |
| 输入与列表 | 留言、收据、筛选区及手机填写票高度平滑变化，排序行移动；不重建无关填写区域 |
| 操作反馈 | 按钮背景与轮廓过渡，堆叠通知顺序位移，无持续漂浮或循环装饰 |

快速操作可打断动画并清理退出节点，不闪回旧内容。遵循系统“减少动态效果”，直接切换状态。菜单支持方向键、Home / End、Escape，关闭归还焦点；弹窗限制焦点并在关闭后恢复页面交互。

## 实现边界

所有交易、关闭、删除、隐藏和封禁均只修改示例内存，刷新恢复；正式服务端仍须验证权限、金额、OAuth 身份、渠道支付状态和操作幂等。前端框架可调整，最终布局、组件复用、状态、文案与交互行为以这里的成品为基准。
